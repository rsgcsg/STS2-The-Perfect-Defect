# B pipeline execution record

Scope: developer data delivery and cloud execution, not model research or scientific
qualification. Platform and STPD remain independently versioned. One Platform Mod and
one STPD developer entry point compose public packages. Models remain external artifacts.

## Frozen ownership

Platform owns native recording, close evidence, release-bound packing, typed verification
and durable delivery. STPD owns source admission, Dataset and research artifacts, the Hub,
operational database, worker scheduling and provider adapters. Hub states cannot confer
Human origin, native authority or research qualification.

One CPU Hub, one private S3-compatible store (R2 target), one automatic provider (Modal
target), one existing STPD worker implementation. Local/fake providers are testing seams.
No public signup product, multi-cloud bidding, new models, cloud inference, cloud STS2,
simulator or RL. No raw evidence, weights or secrets in Git.

## Ordered delivery

1. Resolve live bases/rules and write the architecture contract.
2. Platform fixed collection tools and close-reconciled persistent outbox.
3. Independent cloud receipt, integrity verification and incident accounting.
4. Version-pinned bundle3 adapter, occurrence lineage, Dataset admission/reload.
5. Frozen feature jobs followed by existing TrainingInput/Run execution.
6. Developer entry point, status/report and bounded artifact download.
7. Root tests, independent review, exact-head CI, real store/GPU failure checks.
8. Exact runtime/Human gate as required, final audit and repository closeout.

Each source owner works on its own branch/worktree. Platform source changes merge normally;
STPD follows its governance and requalifies source-bound evidence after integration.
Current source and runtime truth can refine implementation, never lower the admission gate.

## Acceptance dimensions

- Engineering: cross-process close/outbox, tamper, duplicate upload, permission revocation,
  source drift, Dataset reprojection, lease fencing, checkpoint and publication tests.
- Service: exact deployed image/config, actual conditional storage semantics, bounded GPU
  execution, output readback, cleanup, database backup/paused restoration.
- Human/data: immutable real session import and sufficient independent run components;
  synthetic fixtures never stand in for real Full-Run Dataset qualification.

The two PR25 Human runs are useful adapter evidence but cannot bypass the existing minimum
of three independent components for train/dev/test. Discover existing qualified evidence
first; request Human collection only if the required population is absent.
